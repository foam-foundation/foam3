# FOAM Messages: Usage and Migration Guide

## Overview

FOAM's `messages:` feature provides a built-in internationalization (i18n) system for defining translatable strings within models. Messages are defined as axioms that install properties on classes, resolving to localized strings based on the current locale.

## Defining Messages

### Basic Static Messages

Add a `messages` array to your model definition with message objects:

```javascript
foam.CLASS({
  package: 'foam.core.auth',
  name: 'User',
  messages: [
    { name: 'USERNAME_REQUIRED',    message: 'Username required' },
    { name: 'INVALID_FIRST_NAME',   message: 'Invalid characters in first name: ' },
    { name: 'RESET_PASSWORD_SENT',  message: "Password reset request sent." }
  ]
});
```

This installs properties like `USERNAME_REQUIRED` on the class that return the message string.

### Multi-Language Support

Use `messageMap` to provide translations for different locales:

```javascript
messages: [
  {
    name: 'MY_STRING',
    messageMap: {
      en: 'English',
      fr: 'Francais',
    }
  }
]
```

The system resolves messages based on `foam.locale` or `foam.language`, falling back to English.

### Template Messages with Parameters

Enable the `template` flag to use `${}` placeholders for dynamic content:

```javascript
messages: [
  {
    name: 'MSG_CONSTANT1',
    message: 'Message text with one ${templateKey1} or more ${templateKey2} template keys',
    template: true
  },
  {
    name: 'MSG_CONSTANT2',
    message: '${this.MSG_CONSTANT1} or ${this.propertyName}',
    template: true
  }
]
```

Template keys resolve from:
1. Explicitly provided values during rendering
2. `this[key]` for instance properties or other class constants
3. Dot notation for nested FObject properties.

**Usage in views:**
```javascript
this.E().add(this.MSG_CONSTANT1({ templateKey1: this.data.name }))
```

## Porting Hardcoded Strings

### Step 1: Identify Hardcoded Strings

Look for string literals in:
- Property labels
- Validation error messages
- UI text in views
- Choice options

### Step 2: Define Messages

Add messages to your model for each hardcoded string:

```javascript
// Before
properties: [
  {
    name: 'enabled',
    tableCellFormatter: function(value, obj) {
      this.add(value ? 'Y' : 'N');
    }
  }
]

// After
messages: [
  { name: 'ENABLED_YES', message: 'Y' },
  { name: 'ENABLED_NO', message: 'N' }
],
properties: [
  {
    name: 'enabled',
    tableCellFormatter: function(value, obj) {
      this.add(value ? obj.ENABLED_YES : obj.ENABLED_NO);
    }
  }
]
```

Real example from `Script.js`.

### Step 3: Use in Views and Methods

Replace string literals with message references:

```javascript
// Before
choices: [
  [4, 'Low'],
  [5, 'Medium'],
  [6, 'High']
]

// After
messages: [
  { name: 'PRIORITY_LOW', message: 'Low' },
  { name: 'PRIORITY_MEDIUM', message: 'Medium' },
  { name: 'PRIORITY_HIGH', message: 'High' }
],
// In property view
view: function(_, X) {
  return {
    class: 'foam.u2.view.ChoiceView',
    choices: [
      [4, X.data.PRIORITY_LOW],
      [5, X.data.PRIORITY_MEDIUM],
      [6, X.data.PRIORITY_HIGH]
    ]
  };
}
```

## Property-Level Internationalization

For property values that need i18n, use the `I18NString` property type:

```javascript
{
  class: 'I18NString',
  name: 'displayName'
}
```

`I18NString` automatically wraps values with `foam.i18n.Lib.createText()` for translation.

## Automated String Extraction

FOAM provides a script (`scripts.jrl`) to automatically extract strings from models and create Locale entries for translation. This script:

1. Iterates through all used models
2. Extracts `messages` entries and creates Locale objects
3. Extracts property labels and values
4. Creates placeholder translations (e.g., appending ' fr' for French)

## Translation Management

Use the `TranslationConsole` to manage translations at runtime. It allows searching for missing or existing strings and updating them in the `localeDAO`.

## Notes

- Messages are installed as class properties (accessed via `cls.MESSAGE_NAME`) and instance properties (accessed via `this.MESSAGE_NAME`).
- The `MessageTemplateParser` uses FOAM's grammar-based parser system to handle template substitution.
- Set `foam.locale` to change the active language (defaults to 'en').
- The system integrates with the broader i18n infrastructure including `Locale` objects stored in Journal files and `ClientCacheTranslationService` for performance.
